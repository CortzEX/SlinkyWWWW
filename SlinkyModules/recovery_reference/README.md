# Module source recovery

The top level has one `.cpp` decompiler view for each of 68 identifiable module labels in the supplied `lib_win`: 66 registered modules and two named code blocks, Chest Stealer and Speed, that are absent from the recovered registry. The views include 425 functions in candidate module code intervals, including all 171 registered callback slots, plus four explicit references outside their intervals. The interval assignments use code proximity and are not proof of ownership. Block In's registered UI and settings pointers overlap Speed's named routines; [manifest.json](manifest.json) records that ambiguity.

The binary does not contain the original C++ source. The top-level `.cpp` files are Ghidra pseudocode with inferred names and types; they are **not buildable source**. The first lines of each callback identify a separately recovered C implementation and its differential verification report. [manifest.json](manifest.json) records every RVA, source path, and hash. [call_graph.json](call_graph.json) traces direct native calls from the 425 candidate functions: 415 distinct external targets and 257 indirect transfer sites still need ownership or implementation review.

Several UI/settings decompiler views differ from the recovered runtime image. For those routines, the generated C++ follows the runtime instructions and is checked against them; the corresponding top-level pseudocode remains a historical analysis view.
